## 1. 为什么不能只比较选择器优先级

一个元素可以被多条规则匹配，但每个属性最终需要一个值。**层叠**是挑选声明的算法，**优先级**只是算法中的一部分，**继承**则是在缺少直接值时从父元素获得某些属性值的机制。三者混为一谈，会导致不断加 ID 或 `!important`。

本节以普通文档中的作者样式为主，再说明用户样式、动画与层的边界。实验使用支持 `@layer` 的现代浏览器。

## 2. 核心术语与比较规则

| 术语        | 它解决的问题                     | 例子                                  |
| ----------- | -------------------------------- | ------------------------------------- |
| 来源 origin | 浏览器、用户、网站作者谁提供声明 | 浏览器默认给标题设置字体大小          |
| 重要性      | 是否进入 important 等优先组      | `color: red !important` 改变比较组    |
| 层 layer    | 在同一来源内安排样式优先顺序     | 基础层、组件层、覆盖层                |
| specificity | 同组选择器谁更具体               | ID、类/属性/伪类、类型/伪元素逐列比较 |
| 继承        | 没有直接声明时能否沿父级取值     | `color` 常继承，`margin` 不继承       |

简化比较顺序是：先筛掉不适用的规则，再比较来源与重要性及层，之后比较优先级、作用域接近度，最后才比较出现顺序。`@scope` 的接近度仅在前面条件相同的适用场景参与，不是所有页面都有这个步骤。

同为作者普通声明时，未分层声明优先于有层声明；层内普通声明后声明的层优先。**important 会反转层顺序**，早层的重要声明优先于晚层，分层重要声明优先于未分层重要声明。内联样式、动画和过渡还有独立位置，不要把它们套进普通选择器比较表。

## 3. 推导一个具体结果

先预测：`#title` 是 ID，为什么它仍可能输给只有一个类的规则？保存以下完整文件为 `cascade.html`：

```html
<!doctype html>
<meta charset="utf-8" />
<title>层叠实验</title>
<style>
  @layer base, components;
  @layer base {
    #title {
      color: red;
    }
  }
  @layer components {
    .title {
      color: blue;
    }
  }
  .title {
    color: green;
  }
  article {
    color: purple;
    margin: 30px;
  }
  .reset {
    color: inherit;
    margin: unset;
  }
</style>
<article>
  <h1 id="title" class="title">层叠决定胜者</h1>
  <p class="reset">观察继承与重置。</p>
</article>
```

| 候选声明            | 进入哪个比较组   | 是否获胜                   |
| ------------------- | ---------------- | -------------------------- |
| base 层 ID 红色     | 作者普通、有层   | 输给更晚的 components 层   |
| components 层类蓝色 | 作者普通、有层   | 输给未分层普通声明         |
| 未分层类绿色        | 作者普通、未分层 | 最终绿色                   |
| 父元素紫色          | 可继承值         | 标题有直接声明，不依靠继承 |

决定性证据不是“绿色写在后面”，而是它处于更高的普通作者层级。把绿色规则移动到最前面，仍应绿色。然后去掉绿色规则，蓝色胜出，尽管红色用了 ID。

## 4. 优先级不是十进制加分

同一比较组内，`#app p` 可理解为 `(1,0,1)`，`.card .title` 是 `(0,2,0)`，按列从左到右比较。十个类不会“进位”为一个 ID。`:where(...)` 的自身优先级为零；`:is(...)`、`:not(...)` 的参数会影响优先级，不能按普通伪类机械加一。

`inherit` 强制从父元素继承；`initial` 使用规范初始值；`unset` 对可继承属性等同 inherit，否则等同 initial。示例中段落继承紫色，但 `margin: unset` 不会继承父元素的 30px。

## 5. important、动画与边界

普通声明通常按浏览器、用户、作者的方向提高优先级；重要声明的来源优先级反转，允许用户为可访问性覆盖网站。关键帧动画值高于普通值，important 高于动画；正在过渡的值又有更高优先级。这里的“正在过渡”是过渡生命周期中的值，不是写了 `transition` 就永远压过所有规则。

错误做法是为了修复组件颜色，给全局 `*` 添加 `!important`。可观察结果是主题、禁用态和用户覆盖一起被破坏。修复时先在开发工具找到获胜声明，明确组件层边界，移除不必要的覆盖，再考虑是否确有重要声明需求。

## 6. 可维护的样式组织

第三方样式可放在较早层，自身组件放在后层；同一组件保持低而稳定的优先级。父元素设置文本颜色适合主题继承，但组件的直接声明不会因父级选择器“更强”而自动被覆盖。不要用父级 ID 的强度推断子元素结果。

## 7. 练习与验收

1. 给三个颜色声明全部加 important，预测结果后验证。提示：层顺序反转；验收应明确比较的是哪组声明。
2. 比较 `.title`、`:where(#title)`、`:is(#title,.title)`。验收为每个选择器写出优先级，而不把匹配范围当作优先级。
3. 将段落改为 `color: initial` 与 `color: unset` 各运行一次。验收说明为什么“重置”并非只有一种意思。

复习清单：适用性→来源/重要性/层→优先级→作用域接近度→顺序；继承不参与子元素直接声明的“比赛”。
